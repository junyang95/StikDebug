# 买家反馈修复：坐标、停止定位、VIP 校验

当前打包版本：0.1.5（构建号 6），未签名 Release IPA。界面改进与布局验证见 [自适应布局记录](adaptive-layout-2026-10.md)。

## 行为

- 手动停止、目标完成：结束步数统计与行走，在最后的 GPS 坐标继续定点重发；前台 1 秒、后台 3 秒。切换模式不会取消停留。
- 暂停：停止移动并继续定点；恢复行走时交回移动控制器。
- 恢复真实定位：等待正在发送的命令与停止流程完成，取消全部重发后发送 clear。只有此操作主动清除位置。
- 停留仍依赖 App 后台保活、VPN 与设备通道；系统终止 App 或通道断开后的行为需要真机验证。

## 地图坐标

App 内部坐标、输入框、收藏、最近地点、GPX、路线计算和设备命令统一为 WGS-84。地图校正只发生在 MapKit 的输入输出边界：点选、搜索、手绘、标记、路线请求与结果、地图取景。

位置页右上角菜单和设置页可选：

- 标准地图（WGS-84）：默认，保持原来坐标语义。
- 高德地图（GCJ-02）：对使用偏移底图的中国区域做双向转换，覆盖香港、澳门；台湾、日本、欧美常用目的地保持原样。

截图坐标 `22.291800, 114.179000` 若来自 GCJ-02 底图，反算 GPS 约为 `22.2946, 114.1740`，确实相差数百米。但买家未说明选点来源和地图提供方，因此这只能验证一种可能原因，不能确认现场根因。不要依据 UI 语言或手机地区自动切换。Apple 开发者论坛也有[地图坐标模式未向开发者公开的问题](https://developer.apple.com/forums/thread/787990)。

遇到此偏差，可让买家选择高德校正、重新在目标道路上点选，再与游戏对照。手动输入与 GPX 必须为 WGS-84；旧收藏/路线没有记录来源，不能安全地批量转换，发生偏差时应重新选点保存。

## 原生授权

校验编译进主程序，定位命令层也会拦截。删除 `libwowvipguard.dylib` 或 `wowvip.plist` 不会关闭原生校验。

1. 使用已配对设备通道的 lockdownd `UniqueDeviceID`，不使用可修改 plist 的 UDID。
2. 请求固定 HTTPS 接口 `https://wow-app.store/api/vip-license.action`，发送 `DEVICE_UDID` 和随机 `X-VIP-NONCE`。
3. 验证固定的生产 P-256 公钥、DER 签名、UDID、nonce、签发时间、`isVip`、`isBanned`、状态及到期时间。
4. 启动时先从 Keychain 恢复已验证的签名授权，再执行 VPN 和环境检查。启动与回前台复查（30 秒去抖），运行时每 60 秒复查；定位定时器也检查授权。
5. 网络故障、超时、非 200 响应、维护页、签名或格式异常均保留此前有效的本地授权。宽限从最后一次成功联网验证的服务端签发时间起最多 72 小时，并受 VIP 到期日约束；离线重试不会续期。只有通过签名、UDID、nonce 和时间校验的封禁、过期或未授权结果才删除缓存。首次激活必须联网；纯离线设备不会实时收到封禁。
6. 新连接的定位通道再次读取 UDID，与授权绑定核对。读取失败、缺少字段、缺少授权均不放行。恢复真实定位始终可用。

缓存保存在本机 Keychain，并绑定已读取的 UDID、目标地址和配对文件 SHA-256。App 容器路径变化不会使同一配对文件的缓存失效；配对内容变化后必须重新核对设备。可在读取真实 UDID 后迁移 0.1.1 的有效签名缓存。

### 验证按钮与超时

- 设置页“重新验证授权”和顶部“验证”直接触发校验，立即显示进度，验证中可取消后重试。
- 校验不再等待完整环境检查或 DDI 操作。读取设备使用独立通道，最多等待 8 秒；服务器通常按 10 秒无数据超时处理，含系统联网等待的总时限为 60 秒，可随时取消。
- 超时或取消后忽略旧请求的迟到结果。底层设备调用尚未返回时不再堆积设备读取；不会阻塞定位重发队列。
- 有效离线授权在设置中显示实际截止时间，重启 App 后仍可恢复。

## GPX 文件选择（0.1.4）

- 修复导入选择器可能将“我的 iPhone”中的 `.gpx` 文件置灰的问题：在 `Info.plist` 中补齐 `com.topografix.gpx` 的后缀、MIME 和 XML/data 声明，并允许文件提供方将文件标记为普通数据或动态类型。
- 兼容 `.gpx` 和 `.GPX`；无需修改文件后缀。选择器可显示其他普通文件，导入时再校验支持的扩展名和实际内容，错误格式会显示提示。
- 将原有解析器从视图提取为独立实现以直接测试真实导入流程。损坏或不含坐标的 GPX/XML、无有效坐标的 JSON 不再回退到逐行提取数字，避免将版本号、时间等元数据误当成定位坐标。
- 回归覆盖 GPX 导出再导入、轨迹/路线/单点、大小写后缀、普通和动态文件类型、无效内容，以及 KML、GeoJSON、CSV、TXT。保留 WGS-84 原始坐标。
- 类型声明依据：[Apple 文件类型声明文档](https://developer.apple.com/documentation/UniformTypeIdentifiers/defining-file-and-data-types-for-your-app)。构建产物额外检查 GPX 声明确实存在；买家真机的文件选择器仍需更新后验收。

## 首次联网权限（0.1.3）

- 授权请求使用独立 URLSession，并开启 `waitsForConnectivity`。实际访问网络时由系统决定是否显示权限弹窗；等待期间显示允许联网的提示，用户可取消或打开 App 设置。
- 网络恢复、蜂窝限制解除、VPN 连上或从系统设置返回时，自动重试尚未完成的验证，不受普通 30 秒检查间隔限制。蜂窝状态只用作重试提示，不用于阻止 Wi-Fi 请求。
- 若连接恢复事件恰好发生在旧请求结束前，合并成一次待重试；成功、收到可信拒绝或用户取消后清除待重试，迟到回调不会覆盖新状态。
- 未联网或未允许联网不表示非 VIP。已有有效签名缓存继续遵守原 72 小时宽限，首次激活仍需联网成功验证。
- 权限页区分无线数据和本地网络，并删除“普通 Wi-Fi/蜂窝访问不是用户授权项”的笼统提示。
- API 依据：[Apple waitsForConnectivity](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/waitsforconnectivity)。自动测试覆盖授权服务与等待配置，系统首次权限弹窗仍需用全新安装的真机验证。

## iOS 27 启动指引

iOS 27 或更高版本尚未完成有效配对时，启动直接展示现有“本机配对”步骤；每次启动最多自动展示一次，配对完成后跳过。关闭后可从设置再次打开。配对指引展示期间暂缓环境检查，返回前台不会重复弹出。

这阻止了简单删除外置库的绕过方法。主程序仍可被逆向修改，客户端代码不能保证绝对防破解。

## 发布顺序

2026-09-30 线上只读检查：`/api/vip-license.action` 返回 HTTP 200，但签名 payload 仅含 `udid/status/expireAt/nonce/ts`，仍缺少 `isVip` 和 `isBanned`。0.1.2/0.1.3 原生客户端会拒绝这个旧格式，因此部署以下后端变更是首次验证的前提；单独更新 App 无法解决此项。

1. 先部署 `lunabox-svc-dashboard` 的 `VipLicenseService` 更新。`banned=true` 优先返回 `BANNED`，签名 payload 增加 `isVip` / `isBanned`。旧 dylib 会把未知状态当作未授权，因此保持拒绝行为。
2. 核对线上公钥与 `VipLicenseVerifier.publicKeyBase64` 一致。轮换生产密钥需要同步更新 App；不要把私钥放进 App。
3. 构建、重签并分发新版 App。原生校验不依赖旧注入开关，也不读取 `freeMode`；这版定位功能仅向有效且未封禁的 VIP 开放。
4. 真机验证有效 VIP、非 VIP、过期、封禁、离线、删除外置 dylib 后重签，以及香港选点和后台路线停止。
